bcrp-scraping

Librería de metodologías de web scraping reutilizables. No es una colección de scrapers: es el núcleo de patrones validados que cada nuevo scraper (inmobiliario, empleo, diarios/PDF, APIs) reutiliza en vez de reinventar.

1. Objetivo

Convertir el aprendizaje real de los proyectos de scraping del BCRP en una metodología reutilizable para agentes IA (Claude, Codex, Antigravity, Gemini…), de modo que construir un scraper nuevo no empiece de cero ni reinvente patrones ya resueltos.

Reutilizar, no reinventar

Anti-bot, historial, calidad, cache de IA, formato auditable: ya están en core/.

Trazabilidad institucional

No se optimiza para "que corra una vez", sino para memoria histórica, evidencia auditable y reproducibilidad.

Estándar de estructura

Todo scraper nuevo se ve igual: misma cantidad y tipo de archivos, copiando una plantilla.

Contrato cross-agente

AGENTS.md es el contrato que cualquier modelo de IA lee antes de escribir código.

2. Cómo funciona

El repositorio es metodología pura — no contiene scrapers de producción. Tiene dos piezas:

  • core/  Patrones reutilizables y sector-agnósticos. Se cambian con cuidado. Nunca importan del código de un proyecto.
  • plantilla_proyecto/  La estructura estándar de un scraper nuevo. Se copia a <mi_proyecto>/ y se rellena.

Cada scraper real (inmobiliario, empleo, diarios/PDF) vive en su propia carpeta/repo, copia la plantilla y trae de core/ sólo lo que importa (generación selectiva + poda, para no arrastrar código muerto).

HTTP-first. El navegador es la excepción, no el default. Orden: API/JSON/XHR → HTML server-side → __NEXT_DATA__ sin navegador → y sólo si nada alcanza, Chrome (undetected-chromedriver).

3. Estructura del repositorio

bcrp-scraping/ ├── AGENTS.md ← contrato para agentes IA ├── README.md ← entrada para humanos ├── guia.html ← esta guía ├── core/ ← núcleo reutilizable (metodología) │ ├── utils/ http/ ingesta/ redux/ browser/ limpieza/ │ ├── modelos/ contratos.py extractor_ia/ historial/ │ ├── calidad/ mantenimiento_frontend/ snapshots/ │ ├── tipo_cambio/ nse/ reportes/ poda.py logging/ ├── plantilla_proyecto/ ← estructura ESTÁNDAR de un scraper nuevo │ ├── config.py modelos.py limpieza.py scraper.py │ ├── extractor_ia.py main.py │ └── portal_scrapers/ (portal_a.py, common.py) ├── docs/ ← guías de metodología (.md) └── tests/core/ ← tests del núcleo (sin red ni Chrome)

El estándar de un proyecto

Copiar plantilla_proyecto/ produce siempre el mismo conjunto de archivos (imports internos relativos, así que renombrar el paquete no rompe nada). Esa uniformidad es deliberada: cualquiera —humano o IA— encuentra las cosas en el mismo lugar.

4. Módulos de core/

MóduloQué aporta
core.httpHTTP-first: HttpClient (requests + retries + throttle) y detección de anti-bot. Primera opción ante un portal.
core.ingestaPDF: lectura por columnas, extracción de tablas (con y sin bordes) y segmentación documental por código/sección.
core.reduxParser de __NEXT_DATA__ + búsqueda recursiva para SPAs Next.js, sin navegador.
core.browserBrowserManager con undetected-chromedriver y parches anti-bot. Sólo si el portal lo exige.
core.modelos · core.contratosAnuncioBase, RefAnuncio y el Protocol PortalScraper que declara el transporte (http/browser/hybrid).
core.extractor_iaDeepSeekExtractor + cache SQLite por (publicacion_id, descripcion_hash, campo): no se quema un token al reprocesar lo mismo.
core.historialSQLite acumulativo con ciclo de vida (nuevo/repetido/desaparecido/baja) + seguridad: listado parcial, anti-colapso y retiro por vejez.
core.calidadCompuerta pre-IA (umbrales + señales) + detección de duplicados cross-source como señal (nunca borra).
core.mantenimiento_frontend · core.snapshotsEvidencia auditable cuando un portal cambia su HTML: reporte Markdown clasificado + snapshots por etapa.
core.tipo_cambioBCRP DataAPI + cache + conversión auditable (columnas estimadas en rojo, no destructiva).
core.nseClasificación NSE por lookup (sin ML mientras la base esté desbalanceada).
core.reportesExcel acumulativo multi-hoja con dedup + formato visual BCRP, regenerable desde SQLite.
core.podaCompuerta de higiene: detecta módulos copiados sin importadores (evita código muerto).
core.utils · core.loggingnormalizar_enlace canónico, hashes, publicacion_id; logging por corrida.

5. Flujo de una corrida

CLI → scraper (rutea al portal_scraper: Redux → DOM → regex) → limpieza (helpers de core.limpieza + columnas de periodo) → core.calidad.evaluar_cobertura │ DEGRADADO → degradadas/ + reporte de mantenimiento (NO continúa) ▼ OK / ADVERTENCIA → extractor_ia (cache → fallback regex → DeepSeek si falta) → historial.registrar_corrida (ciclo de vida + seguridad de bajas) → Excel acumulativo (Consolidado + Diagnostico) → [opcional] tipo de cambio + formato visual
SQLite es la fuente de verdad longitudinal. El Excel es una vista cómoda: si se pierde, se regenera desde SQLite sin re-scrapear.

6. Crear un scraper nuevo

# 1. Copiar la plantilla estándar y renombrarla
cp -r plantilla_proyecto mi_proyecto

# 2. Rellenar config.py, modelos.py, portal_scrapers/...
#    (imports internos relativos: nada que reconectar)

# 3. Corrida acotada, primero sin IA
python -m mi_proyecto.main --portal portal_a --paginas 1 --sin-ia

El paso a paso completo está en docs/agregar_nuevo_sector.md. Antes de escribir código, el agente pasa la compuerta de intake: para qué sirve el scraping, qué universo, qué horizonte, y qué datos hay realmente en la fuente.

7. Reglas que no se rompen

ReglaPor qué
core nunca importa del proyectoDependencia de un solo sentido. El proyecto importa core/, jamás al revés.
Calidad antes de IADatos degradados no contaminan el historial ni queman tokens; van a degradadas/.
normalizar_enlace es únicoHistorial y cache comparan la misma forma canónica; si difieren, no hay hit.
Lectura en cascadaRedux → DOM → regex → None. Nunca asumir una sola fuente.
Listado parcial no marca bajasUn universo truncado no prueba que un aviso desapareció.
Similitud nunca borra solaDedup exacto por enlace es automático; la similitud sólo SEÑALA para revisión humana.
TC no sobrescribe lo observadoSólo agrega columnas estimadas auditables (en rojo).
IA es adaptador, no metodologíaCambiar de proveedor cambia el adaptador, no las reglas de negocio.

8. Para agentes IA

Ante cualquier pedido de scraping del BCRP, el agente —Claude, Codex, Antigravity, Gemini— primero lee AGENTS.md y core/ antes de escribir código. No arranca de cero ni reinventa un patrón que ya vive en core/.

  • Convención de capas y cuándo subir un patrón a core/ (regla del "aparece en ≥2 proyectos").
  • Compuerta de intake (propósito + hallazgos) antes de construir.
  • Mantenimiento ante cambios de frontend: reporte auditable + snapshots para una IA auditora.
  • Anti-patrones: abrir el navegador "por las dudas", parsear strings cuando hay JSON, mutar el historial con corridas degradadas.
